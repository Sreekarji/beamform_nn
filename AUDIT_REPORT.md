# Code Audit Report

**Repository:** `Sreekarji/beamform_nn`  
**Audit scope:** all Python source files, tracked data/plot dependencies, README/report claims, imports, paths, numerical conventions, and the new HFSS integration path.  
**Audit date:** 2026-10-11 (UTC)

## Executive summary

The codebase is a coherent narrowband N=8 MVDR demonstration. The core steering-vector convention, Woodbury MVDR reference, null-aligned synthesis chart, training targets, and evaluation metrics are mutually consistent for the documented experiment. The analytical scripts were syntax-checked and the physics verification, dataset generation, recommended training path, ablation artifacts, and plot generation were exercised with Python 3.11, NumPy, PyTorch, and Matplotlib.

The most important engineering issue found was a numerical edge case in `DistortionlessProjection`: an exactly zero raw gain produced a zero denominator despite the comment claiming that the denominator was protected. That is fixed in this branch. Other fresh-run and reproducibility issues were also addressed: repository-relative paths, output-directory creation, import-time dataset generation, Matplotlib empirical-CDF compatibility, and the hard-coded N=8 tau scale in `BeamNet`.

The remaining limitations are primarily scientific rather than syntax failures: the model is an ideal uncoupled point-source array, the random grid split measures interpolation rather than geometric generalization, close-angle samples are ill-conditioned, and the headline metrics supplied in the project brief do not exactly match the saved artifact metrics. These are documented below and in the rewritten `README.md`.

## Severity legend

- **Critical:** prevents a normal clean run or invalidates the primary result.
- **High:** can silently produce an incorrect numerical result or misleading comparison.
- **Medium:** reproducibility, portability, or edge-case risk.
- **Low:** documentation, maintainability, or non-default-path issue.

## File-by-file findings

### `physics.py`

**What is correct**

- `steering_np` and `steering_t` implement the same half-wavelength convention, `exp(j n pi sin(theta))`.
- `mvdr_np` uses the Woodbury identity correctly for `R = G P G^H + sigma_n I`; it solves only a 2-by-2 system and normalizes to unit desired response.
- `j_min_np` is consistent with `J_min = 1/(a_s^H R^-1 a_s)`.
- `exact_null_np`, `exact_null_basis`, `synth_subspace`, and `synth_null_aligned` use the same conjugation convention. In particular, `gamma = a_i^H a_s/N` makes `u^H a_i = 0`.
- The split real/imaginary ordering is consistent with `gen_dataset.py`, `to_complex`, and `to_real_split`.
- The normalized null and SINR definitions are scale-aware and match the README/report definitions.

**Finding fixed — Medium numerical edge case**

`DistortionlessProjection.forward()` previously formed a phase-preserving clamped denominator using `c / abs(c)` and could still produce `0` when `c == 0`. A zero-initialized or exactly cancelling raw output therefore divided by zero. The implementation now substitutes phase one for a zero complex gain before applying the detached minimum-magnitude denominator, and then retains the exact additive constraint correction.

**Remaining risks**

1. `exact_null_basis` subtracts nearly equal steering vectors. For source/interferer separations near zero, cancellation in complex64 can make the basis inaccurate. The data generator excludes differences below 3°, but the public function does not reject or warn on such inputs. This is a documented domain restriction, not a complete general-purpose solver.
2. `sinr_db_t` can return `-inf` for an exactly zero weight vector. That is mathematically appropriate but should be handled by a caller if finite losses are required.
3. `mvdr_np` accepts nearly coincident angles and very unusual powers without a condition-number check. It is stable for the repository grid but should use a diagnostic or diagonal loading for generalized data.
4. `verify_physics.py` intentionally retains an explicit inverse as a comparison baseline; production labels use the solve/Woodbury path instead.

### `models.py`

**What is correct**

- `BeamNet` provides the documented `raw16`, `subspace`, and `nullaligned` output charts.
- The subspace chart uses `alpha = (1 - beta rho)/N`, which makes `a_s^H w = 1` analytically.
- The null-aligned chart uses `g = 1 - tau rho`, and the resulting null response is directly controlled by `tau`.
- `features='ang2'` matches the recommended model and the saved checkpoints. The optional five-feature path is internally consistent.

**Finding fixed — Medium portability/generalization issue**

`DELTA` and the default `tau_scale` were derived from `N=8` even though `BeamNet` exposed an `N` argument. A caller constructing `BeamNet(N != 8)` could silently use a scale appropriate to the wrong array. The default is now computed from `N`; N=8 produces the same scale and remains checkpoint-compatible.

**Remaining risks**

- `BETA_SCALE` is still a heuristic fixed scale, so it is not a fully generalized normalization for arbitrary N, powers, or close angles.
- The model assumes angle inputs are floating point tensors with shape `(B, 2)`; invalid shapes are not given a custom error message.
- The close-angle conditioning restriction is not enforced inside `forward()`. A future generalized API should either reject a small `|sin(theta_s)-sin(theta_i)|` or switch to a numerically stable basis/parameterization.

### `gen_dataset.py`

**What is correct**

- The grid is `[-60, 60]` degrees inclusive with `|theta_s - theta_i| >= 3°`.
- NumPy labels are calculated in float64; both `(alpha, beta)` and `(g, tau)` reconstructions are checked against `W`.
- The split is deterministic with seed 42 and is saved alongside the data.
- `Y` uses the same `[real(W), imag(W)]` layout expected by the physics utilities.

**Findings fixed**

1. Generation used to happen during import, so a library import could overwrite `data/dataset_N8.npz`. It is now import-safe and runs through `main()`.
2. The output path now resolves from the source file and creates `data/` when needed, instead of depending on the process working directory or a pre-existing directory.

**Remaining risks**

- The generator has no command-line options for N, powers, grid, or minimum separation; those are module constants. This is suitable for a reproducibility artifact but not a reusable data-generation library.
- With the current 121-by-121 grid, 14,641 pairs are possible and 599 are removed, leaving 14,042. An earlier version of `report.md` used the inconsistent “14,520 pairs / 478 removed” count; that prose is corrected in this branch.
- At the accepted 3° boundary, the scaled null target can be substantially larger than the typical target. The generator prints the range so this is visible.

### `train_ablation.py`

**What is correct**

- All variants use the same saved split and the same architecture/optimizer recipe where intended.
- `evaluate()` computes normalized null depth, MVDR-minus-NN SINR gap, relative weight error, and grid-based pointing error on the held-out split.
- Prediction order remains aligned with `idx_test`, which is required by `make_plots.py`.
- The best validation state is restored before test evaluation.

**Findings fixed**

- Dataset, prediction, checkpoint, and JSON paths now resolve from the repository and output directories are created before writing.

**Remaining risks**

1. The script loads data and constructs loaders at module import. It is safe as a command-line script, but not import-safe as a reusable library.
2. The variant name is `raw16_norm` in the implementation and top-level documentation; saved filenames and README use the same name.
3. DataLoader shuffling is seeded indirectly through global PyTorch state rather than with an explicit per-loader generator. Exact bitwise repeatability across PyTorch versions and thread settings is not guaranteed.
4. The random split puts nearby angle pairs in both train and test. Results measure interpolation on a finite grid, not extrapolation or robustness to unseen geometry.
5. The `full` loss assumes `w` is distortionless. That precondition holds for the null-aligned chart but would not hold for an unconstrained raw16 model if the loss configuration were changed.
6. A finite-validation-state check now raises a useful error instead of attempting to load `None` if every validation loss is NaN.

### `make_plots.py`

**What is correct**

- The six figures use the saved metric/prediction artifacts and the same steering convention as training.
- Test predictions are matched to test angles through `idx_test`.
- The INR and SINR-cost plots use independent analytical references rather than model output.

**Findings fixed**

1. The script previously used `Axes.ecdf`, which is unavailable in older Matplotlib releases despite the README not specifying a minimum version. It now uses a small `step`-based ECDF helper.
2. All input/output paths are repository-relative and `plots/` is created automatically.

**Remaining risks**

- `make_plots.py` is intentionally an artifact consumer: running it before `train_ablation.py` will fail with a missing file. The README now states the required order.
- Figure 3 and the other pattern plots normalize curves to their own peak. This is appropriate for shape comparison but not an absolute gain or realized-efficiency comparison.
- The plot title calls some values “worst” while using the 90th percentile in dB; because deeper nulls are more negative, that percentile is indeed the shallowest tail, but the terminology deserves care.
- The old `pattern_db_abs` helper is not used by the current figures.

### `recommended_solution.py`

**What is correct**

- It is genuinely self-contained and reproduces the recommended two-output chart without depending on the generated dataset file.
- It reports only a held-out split returned by `train()`, not the training set.
- The model, labels, and evaluation use compatible complex64 training and float64 evaluation paths.

**Findings fixed**

- The generated checkpoint is now written to `data/model_nullaligned_recommended.pth` using a repository-relative path rather than an unexplained root-level `model_nullaligned.pth`.

**Remaining risks**

- The constants are intentionally hard-coded for N=8, SNR 20 dB, and INR 30 dB. The class is a project reproduction, not a configurable training package.
- `loss_physics()` and `loss_null_hinge()` are provided but not used by the default training path; this is intentional but should not be described as the default objective.
- The function now raises a clear error if validation never produces a finite loss; it still assumes the default fixed scenario is numerically well behaved.
- It prints validation loss rounded to six decimal places, so very small nonzero values appear as `0.000000`.

### `verify_physics.py`

**What is correct**

- The explicit inverse, Woodbury, and Sherman–Morrison implementations agree to approximately 1e-13 in the reference case.
- It verifies the distortionless constraint, the two-vector subspace residual, INR-dependent null depth, perturbation sensitivity, and SINR cost of a shallow null.
- It uses float64 and is an appropriate diagnostic script.

**Remaining risks**

- It executes at import time because it is written as a report-producing script rather than a module. A `main()` wrapper would make it easier to reuse in automated tests.
- `ref_gain` and the `pointing?` table heading are unused/leftover presentation variables.
- The helper has a module-level N and powers, so its optional `N` argument is not fully general in every function.

### `hfss_overlay.py`

The integration script is designed around two valid HFSS workflows:

1. **Direct combined case export:** one CSV/TAB/TXT file per source-weight case containing an angle and a dB/linear far-field quantity. This is the most reliable first validation.
2. **Embedded complex fields:** one file per port containing complex `Etheta`/`Ephi` versus angle. The script coherently sums those fields with the Python source weights; it explicitly refuses to combine dB-only embedded data.

It reports normalized curve RMSE and writes per-case PNG overlays plus a CSV metrics file. It does not silently infer a coordinate transform: the user chooses `python` signed-angle mode or the documented HFSS spherical-cut mapping and can pass column names/phi selection. This is important because an unnoticed array-axis or conjugation error can produce a visually plausible mirrored pattern.

## Fresh-run checklist

From a clean checkout with dependencies installed:

```bash
python -m py_compile physics.py models.py gen_dataset.py train_ablation.py \
    make_plots.py recommended_solution.py verify_physics.py hfss_overlay.py
python verify_physics.py
python gen_dataset.py
python train_ablation.py baseline nullaligned_mse nullaligned_full
python make_plots.py
python recommended_solution.py
```

The full six-variant ablation is CPU-bound and takes materially longer than the verification or dataset steps. The tracked data/checkpoints make the plotting step reproducible without retraining. The HFSS script can be smoke-tested with synthetic or exported case files and requires no HFSS installation on the Python side.

## Recommended next fixes

1. Add automated unit tests for steering conjugation, distortionless gain, exact-null residual, and `w`/`Y` round trips.
2. Add a grouped or held-out-angle test split to measure generalization rather than grid interpolation.
3. Replace the angle-only, fixed-power input with embedded steering/covariance features for physical validation.
4. Calibrate HFSS port/source conventions with a single element and broadside case before comparing deep nulls.
5. Use complex embedded patterns and an HFSS-derived covariance for the final MVDR comparison; retain the ideal analytical result as a control.
6. Add explicit condition-number diagnostics or a bounded log-magnitude null coordinate for source/interferer separations below 3°.
